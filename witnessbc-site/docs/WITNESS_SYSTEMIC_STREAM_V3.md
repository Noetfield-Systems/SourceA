# WITNESS BC — SYSTEMIC DIGNITY STREAM
Version 3.0 · 23 November 2026 · Product owner: Witness BC (independent venture)

## North star
Find repeatable failures in organizational rules, supervision, or service delivery; build a record strong enough to obtain a response and measure corrected practice. Never target people for identity, sex, orientation, origin, status or personality. Equally avoid implying a single witness proves a systemic pattern.

Public identity: **Dignity first. Systems accountable. People respected.**

## Seven connected operating lanes

### Target intervals, not guarantees
Urgent safety/retaliation flags: internal 1 business day; high: 2; standard: 3. For active cases: next action date visible to the case lead; overdue list prioritized. Actual deadlines for external tribunals take precedence. No service-level guarantee implied, especially while Witness BC is founder-operated.

### Data separation
(1) **Private reporter file:** contact, detailed account, receipt hash, evidence provided, private notes.
(2) **Private operator event log:** owner, priority, next action, route, source classification and verifiable receipts.
(3) **Public editorial stream:** independent, redacted, manually curated static entries. Reports NEVER automatically turn into public entries.
(4) **Reference research:** clearly attributed sources, not Witness BC achievements or filed complaints.

### Richmond calibration: WBC-COMMUNITY-001
- Scope: one particularly problematic McDonald's branch in Richmond, with limited experience at some other McDonald's locations.
- Allegation: repeated discourteous behaviour across different staff observed by a single worker.
- Unknowns: precise branch; policies; whether it is directed, tolerated or incidental; corroboration and franchise response.
- Never generalize to all of Richmond, McDonald's staff, any demographic minority, or an individual.
- First external questions: written delivery pickup policy; franchise owner; grievance process; supervisor oversight; expectations for professional conduct.
- Acceptance for *response requested*: branch identification + documented outbound request to correct operator.
- Acceptance for *corroborated*: independent records and fair alternative explanations reviewed.
- Acceptance for *resolved*: documented policy or practice correction and independent verification (not just reassuring email).

### Canadian/BC route matrix
Workers/platform relationships -> company / franchise / platform; employment standards and WorkSafeBC only when legally applicable.
Private retail service -> company complaint; Consumer Protection BC only if a regulated consumer-law issue.
Protected-ground discrimination -> BC Human Rights Tribunal; one-year general filing window, subject to exceptions; a Witness report does NOT pause it.
Government process fairness -> BC Ombudsperson, appropriate public review body.
Immigration/migrant worker support -> Migrant Workers Centre; low-wage worker support -> Worker Solidarity Network.
Immediate danger -> emergency services, not a Witness public report.

### Security and privacy
BC PIPA principles apply to private organizations. Limit collection to necessary personal details, keep data private and segregated, obtain appropriate consent, avoid automatic public exposure, honor access/correction requests and document a retention/deletion policy. The current single-key operator model is a pilot control; it is **not multi-role identity or enterprise RBAC**. No unattended AI publication or automated allegations. Review DPA, breach response, backups and deletion controls before large-scale sensitive intake.

### Media and distribution
Canonical public Stream /dignity/stream; supporting case /dignity/cases/richmond-delivery and source-specific /dignity/research/* pages. Links and factual headlines only; each card names its evidence level and original source. Provide sitemap, CollectionPage metadata, crawlable links, shareable snippets, right of reply and correction history. Search ranking and media pickup are not verified or guaranteed.

### KPIs (from verified receipts only)
- Real private reports received; first-human review time (not just automated receipt).
- % cases with assigned owner and next-action date; overdue follow-ups.
- Documented outbound requests and attributable replies; response latency.
- Meaningful verified corrections or remedial actions; repeat-issue rate.
- Privacy incidents and correction turnaround.
- Source links and editorially documented external coverage (not impressions invented from nothing).

### Acceptance
- Workstream engine unit tests all category routing, dates, evidence statuses, editorial predicates.
- API preserves confidentiality of report records and validates operator input; event append-only.
- Public Stream contains only selected source-backed research and one explicitly unverified witness case; no production records or private case ids leaked.
- Live mobile/desktop checks, private Blob smoke, production HTTP readback.
- Until new email/app integration has independently verified a send, operator can only record existing, real correspondence receipts; never claim outreach automatically.
